## Step-by-Step Guide

### Step 1: Context Before Output
A request like "write a caption" produces something generic. Describing the actual business, the specific thing being written about, and the tone wanted, before asking for the writing itself, produces something closer to usable. This is why the prompts throughout this library's guides are built around real bracketed details, not left as one line requests.

### Step 2: Specific Feedback Over Vague Feedback
"Make it sound less generic" gives Claude very little to act on. "Avoid this specific phrase and focus on this specific detail instead" gives it something concrete. The more precisely a problem with a draft is described, the more precisely it can be fixed.

### Step 3: Targeted Revisions Instead of Full Rewrites
Asking for a specific line or section to be adjusted, while keeping the rest as is, tends to work better than asking for an entire piece to be redone from scratch, since a full rewrite risks losing whatever was already working.

### Step 4: Recurring Context Belongs in a Project
If the same business background keeps getting pasted into new conversations, that's the signal to set it up once inside a Project instead, covered in an earlier guide in this set.

### Step 5: Every Prompt in This Library Is a Template
The bracketed prompts throughout this library's guides are meant to be filled in with real specifics and adjusted, not used exactly as written. Specificity is what makes the difference between the template and a genuinely useful result.

## Frequently Asked Questions

**Q: Is there a "correct" way to phrase every prompt?**
No, there's no single right format. Specificity and clear context matter more than any particular structure.

**Q: How long should a prompt actually be?**
As long as it needs to be to convey real context. A short prompt is fine for a simple task. A more complex tool, like an Artifact with specific logic, needs more detail, as the examples throughout this library show.

**Q: What if I don't know exactly what I want yet?**
That's a fine place to start. Describing the general problem and asking Claude to help think it through tends to clarify what's actually needed as the conversation goes on.

**Q: Should I worry about "wasting" a prompt by not getting it perfect the first time?**
No, iterating is normal and expected, not a sign anything was done wrong.
